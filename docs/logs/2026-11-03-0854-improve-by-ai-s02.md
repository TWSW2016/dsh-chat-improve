## 结果与证据

- 控制器状态：`{ status: idle|running|ready|error, confirm, truncated, error, notice, original, rewritten }`；动作 `click / confirm / cancel / restore / dismiss / dispose`；`bind(port)` 提供 `getInput / setDraft / focus`。
- 传输：`POST chat-improve/rewrite`（文档相对路径、`credentials: same-origin`、90 s 超时、外部信号转发），失败统一成 `{ ok:false, code }`；超时用 fake timer 测过。
- 注册：`conversation.input.right`（id `chat-improve.improve`，order 10）+ `conversation.input.dock`（id `chat-improve.improve-notice`，order 30，排在 todo/goal/queue 之后、最贴近输入卡）；两者共用 `registerImprove` 返回的一个 disposer。
- 设置：`improvePrompt` 默认 true；关掉时 `syncImprove` 直接 dispose 两个槽，等于完全不注册、不发请求。
- 文案：新增 27 个 key（按钮/提示条/失败原因/设置项），中英各一份，失败原因有独立映射表。

## 决策

- **控制器不碰 DOM 与 fetch**：组件通过 `bind` 注入端口，传输通过构造参数注入。换来的好处是整个流程（含单飞、撤销守卫、dispose）不需要 React 就能测。
- **按钮负责 bind 端口**：`Notice` 只读 `useInput` 与状态，写回统一走控制器的 `port`；避免两个组件各写一份 `setDraft`。
- **端口用 ref 读取最新草稿**：`useEffect` 的依赖只留 `[controller, inputActions]`，否则每敲一个字都要重绑。
- **焦点自愈**：`editor.focus(undefined, { defaultSelection: 'rootEnd' })`，失败退回 `root.focus()`；官方 `InputActions` 没有 focus 座位（步骤 0 已核实）。
- **样式走一次性 `<style>`**：与 `src/mermaid/enhance.js` 的 `injectStyle` 同型，用 `id` 去重，disposer 只删除自己创建的那张。
