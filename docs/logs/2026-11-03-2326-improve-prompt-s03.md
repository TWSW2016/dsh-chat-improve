## 决策

- README 摘录上限保持 1500 字符，不下调到 400：上一轮真实输出里的 `per-origin settings` 正来自摘录后段，砍到 400 会先丢掉这条有价值的细节；本轮先用标签与头部约束，如果真实抽样仍出现"编需求"再降额。
- 用"结尾提醒"而不是重排 prompt 结构：重排要把 `SYSTEM_PROMPT` 拆成 head/tail 并改 `composeSystemPrompt` 的语义与多组测试，收益（把示例挪到最后）与风险不成比例；一行 reminder 已能让最后读到的内容是输出契约。
- 条件化保留 "use it as the first source" 原短语：现有测试锚定它，且语义仍成立（仅在前面加了适用条件）。
- cwd 去重比较用 `resolve()` 而不是字符串相等：会话头给的 `E:/Repos/...` 与 `join()` 出来的 `E:\Repos\...` 只有分隔符不同，字符串比较会误判为两个目录。

## 问题与限制

- 简报与提醒的顺序仍是"指令 → 示例 → 简报 → 提醒"，示例不在最后；如果真实抽样显示模型仍偏向 README 里的功能描述，下一步再做 head/tail 重排。
- `resolve()` 在非绝对路径上会按进程 cwd 解析；当前 cwd/root 都来自绝对路径，没有影响，但单测若改成相对路径会失真。
- 运行中的 Desktop 宿主仍加载旧代码，本步只验证到函数级与单测级，真实模型输出待插件重载后抽样。

## 可复用经验

- 简报去重必须先规范化路径再比较：Windows 下同一目录的两种分隔符写法会让朴素比较失效。
- 给数据块加"可忽略"标注比删数据更安全：既保住有价值的细节，又降低模型过度采纳的概率。
- 在 system prompt 末尾补一行"重申输出契约"是低风险高收益的收束手段，比重排整段指令便宜。
