## 问题与限制

- 计划文档保留旧的时间戳 YAML（`created/updated` 为 ISO 时间）和节级来源表；`check_sources.py` 的 clean 检查会把这些旧格式报为属性错误。没有为了过检重写历史格式，新增日志按 1.0.0-rc.1 的日期与引号格式生成。
- 没有新增“工作区上下文”独立开关；现有 `improvePrompt` 总开关仍然关闭即完全不发请求。若以后要更细的隐私控制，可再加子开关。
- 不读取全局 `~/.dsh/AGENTS.md`、会话历史、git status；这是本轮确认的范围，不是遗漏。
- 引用 chip 的确认条仍未覆盖；真实模型输出仍具不确定性，三条草稿取样通过不等于所有草稿都通过。
- README 是产品文档，不套用 log-deai 的 YAML；本日志只记录其变更来源。

## 可复用经验

- 改 R8 时必须同步 §3.4、§3.5、§3.7 和 README 的“stateless”说法；只改需求表会留下自相矛盾的设计记录。
- 旧日志的 YAML 格式与新技能不一致时，新增文件按新格式写，旧文件保留历史格式并报告，不为过检批量改写。
- 验证产物含 token 时，先 `jq 'del(.url)'` 脱敏，再决定保留还是删除；临时脚本不要留在仓库。
- 收尾提交只包含当前步骤的文档与日志，不把 `.research`、`lib/` 等忽略产物带进 Git。
