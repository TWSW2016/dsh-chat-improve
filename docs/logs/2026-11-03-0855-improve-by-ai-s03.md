步骤 3 完成：补了 `focus.js` / `styles.js` 的 jsdom 测试（各 4 例、2 例），写了 `scripts/verify-improve.mjs`（Playwright，默认拦截改写路由，不烧 token）。`npm test` 121 例全绿。真实 GUI 执行留到步骤 6：需要先部署，且本机拿不到带 token 的 Web URL（脚本要求 `DSH_VERIFY_URL`）。下一步：步骤 4 处理跨会话隔离等边界。

## 目标与请求

按计划步骤 3 完成 happy path 的收尾与验收手段；判据是“真实 GUI 里完成一次改写与还原”。该判据要等部署后才能满足，所以本步先交付可执行的验收脚本与其自检，执行证据记在步骤 6。

## 执行与命令

1. 新增 `tests/improve-focus.test.js`（`// @vitest-environment jsdom`，4 例）：编辑器 `focus(undefined,{defaultSelection:'rootEnd'})`、编辑器抛错退回 DOM focus、无编辑器退回 DOM focus、无 composer 不抛错。
2. 新增 `tests/improve-styles.test.js`（jsdom，2 例）：只注入一张表、二次调用的 disposer 不误删别人建的表。
3. 新增 `scripts/verify-improve.mjs`：`DSH_VERIFY_URL` + 本机 Chrome + `playwright-core`，五个场景（改写+还原、失败+重试、@ 引用确认闸门、关设置后按钮消失），默认 `page.route('**/chat-improve/rewrite')` 返回固定响应，`DSH_VERIFY_REAL=1` 才打真路由；产物写 `.research/verify/improve-*.png` 与 `improve-report.json`。
4. `npm test` → 14 文件 121 例通过。
5. `node --check scripts/verify-improve.mjs` → 语法通过。

## 结果与证据

- 焦点测试证明 `focusComposer` 优先走 Lexical（光标落文档末尾），异常时退回 `root.focus()`，不会抛到 React。
- 样式测试证明幂等注入与“只删自己创建的”语义。
- 验收脚本的关键设计：拦截路由让 UI 行为可重复且零成本；`failNext` 开关单独驱动 502 场景；`@` 引用场景在造 chip 失败时记录 `asked:false` 而不是误报通过。
- 脚本尚未执行（原因见“未决”），`report.json` 还没有证据文件——这一步不声称“真实 GUI 已通过”。

## 决策

- **不在本步跑 GUI**：没有 token 的 URL，`Invoke-WebRequest` 已被 401 拒绝（步骤 0 记录）；强行重试没有意义。验收脚本与执行拆开，执行证据放到步骤 6 部署之后。
- **默认拦截而不打真模型**：UI 回归不需要真实模型；真模型只在 `DSH_VERIFY_REAL=1` 时跑，避免每次回归烧 token。
- **`@` 场景允许降级**：headless 下能否造出真实 chip 不确定，脚本以 `asked:false` 记录事实，不把“没造出 chip”当成通过。
