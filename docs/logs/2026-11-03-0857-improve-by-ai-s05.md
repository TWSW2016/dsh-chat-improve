## 交接摘要

步骤 5 完成：README 增加“Improve by AI”能力、设置项、目录结构、限制与“会发一次模型请求”的说明；`locale/*.json` 与 `package.json` 的描述同步；`docs/verification.md` 增加五行待验收条目、两条限制与两条来源。打包自检 33 个文件、`src/host` 与 `src/improve` 全在包内。下一步：步骤 6 部署 + 真实验收。

## 目标与请求

按计划步骤 5 收尾文档与文案，判据是“README 明说会发一次模型请求；文案无硬编码中文”（文案走 locale 字典，未新增硬编码）。

## 执行与命令

1. 改 `README.md`：能力列表新增一条；Not in scope 补“流式改写、改写后保留 @ 引用”；设置清单新增 Improve by AI；布局树加 `src/host/`、`src/improve/`；已知限制新增六条（外发草稿与隐私、清空引用、单层还原与 8 秒消失、无流式与 90 秒上限、需要模型、无状态）；末行从“no model-visible input”改为“the one model call is not part of the conversation log”。
2. 改 `locale/en.json`、`locale/zh.json` 的 `meta.description`，加“一键让模型改写草稿”。
3. 改 `package.json` 的 `description`。
4. 改 `docs/verification.md`：`updated` 改 2026-11-03；结果表加五行“待验收（步骤 6）”；限制加两条（外发与引用/还原语义）；来源加 `rewrite.js` 与 `verify-improve.mjs`（行号按实际 166 行修正）。
5. 自检：`npm pack --dry-run --json` → 33 个文件，`src/host/*` 与 `src/improve/*` 全部在包内。

## 结果与证据

- README 现在明确写了“Improve by AI sends the draft to the model provider configured for the session… turning the setting off registers neither slot, so no request can happen.”——这条是本功能与“纯展示”定位的分界线。
- 限制条目与实际实现一一对应：整体替换（`setDraft` 清 chip）、单层还原（`store.js` 覆盖式快照）、8 秒（`Notice.jsx` `DISMISS_MS`）、90 秒（`request.js` `REQUEST_TIMEOUT_MS`）、无状态（Host 只发一条 user 消息）。
- `npm pack` 的 33 个文件包含新的 Host/Client 源码，部署时不会漏文件。

## 决策

- **把“会发模型请求”写在 README 的能力条目里，而不是只写在限制里**：用户看能力列表就该知道这一点，藏到限制里等于误导。
- **`docs/verification.md` 先写“待验收”而不是空着**：记录必须反映真实状态，步骤 6 拿到证据后再改成结论。
- **不改 `docs/mermaid-cheatsheet.md`**：与本功能无关，避免无意义 diff。
