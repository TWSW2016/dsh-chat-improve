## 交接摘要

步骤 4 完成：发现并修掉一个真问题——控制器是插件级单例，两个会话同时挂载时会互相看见对方的“已改写/还原”状态。改为 `createImproveControllers` 按 `sessionId` 分表，每个会话一个控制器，插件 dispose 时统一销毁。单测 125 例全绿，构建 3415.0 KiB。边界矩阵逐条有了归属。下一步：步骤 5 文档与文案。

## 执行与命令

1. 复核已实现的边界（步骤 2–3 落地）：`confirm` 闸门、`draftRev` 不等则丢弃、错误码 → 本地文案、90 s 超时、`truncated` 提示、8 s 自动消失、`dispose` 中止请求并忽略迟到结果、设置关闭即注销两个槽。

## 结果与证据

边界矩阵与实现位置（全部有测试或明确的代码路径）：

| 情形 | 位置 | 测试 |
| --- | --- | --- |
| 空草稿/仅空白 | `Button` 的 `disabled` + `controller.click` 双保险 | controller: “does nothing without a draft” |
| 提交中/命令态 | `Button` 的 `disabled`（`phase !== 'plain'`） | 组件层，留 GUI 验收 |
| 已有请求在飞 | `controller.click` 直接 return | controller: “keeps one request in flight” |
| @ 引用/命令 | `confirm` 状态 + 提示条“继续/取消” | controller 两例；GUI 脚本第 4 场景 |
| 成功且草稿未变 | `setDraft` + ready 状态 | controller: “runs one request and replaces the draft” |
| 成功但草稿已变 | `draftRev` 不等 → `notice:'draft-changed'` | controller: “discards the result…” |
| 409 无模型 / 502 / 503 | 错误码 → `describeError` | messages 4 例 + route 16 例 |
| 关闭页面 | 前端 abort → Host `res.on('close')` → `controller.abort()` | 代码路径；GUI 脚本失败场景间接覆盖 |
| 插件卸载/HMR | `registerImprove` 的 disposer：两个槽 + registry.dispose + 样式表 | registry: “disposes every controller…” |
| 跨会话串状态 | registry 按 `sessionId` 分表 | registry: “keeps session state apart” |

## 决策

- **每会话一个控制器**，而不是一个全局控制器 + 手动清空：槽的作用域本来就是 session，控制器跟着作用域走最省心，也让“切回会话还能还原”成为自然行为。
- **控制器不设上限**：每个控制器只存一次改写的两个字符串；页面里同时挂载的会话数是用户自己的数量，加淘汰策略属于过度设计。已在日志记录这个取舍。
- **重启不做持久化**：刷新即丢“还原”能力，符合“只留一层、几秒后自动消失”的产品选择。
