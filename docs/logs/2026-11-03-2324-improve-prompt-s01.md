## 决策

- 保留 33 行 "Every added sentence must resolve a reference, narrow the scope, state a real constraint, or define what done means" 原句不动：它本来就是对的，问题只是规则 2 给了第二条路；改规则 2 后两份清单一致，不再冲突。
- 规则 2 同时禁止 "files to touch" 与 "commands to run"，而不只是禁止 "steps"：上一轮的真实输出既写了步骤，也可能写文件级操作；只禁 "plan" 会留下缺口。
- 不删除规则 3 的 "Do not add generic process boilerplate…" 半句：它已被现有测试锚定，且仍是有效的反例约束。
- 没有加"负例 few-shot"：负例容易被模仿，改用步骤 2 的正例覆盖失败样例。

## 问题与限制

- 第一次测试失败是断言串跨了换行：源码把 "…run: the" 与 "agent that receives…" 分在两行，`toContain('the agent that receives…')` 匹配不到。改为不含前导 "the" 的片段后通过。经验：这个仓库的提示文本是逐行字符串拼接，断言不要跨行写。
- 本步只覆盖规则层；few-shot 仍在示范"读 cwd/分支/AGENTS.md → 改 system prompt"，所以真实模型输出未必立刻改善，需等步骤 2。
- 运行中的 Desktop 宿主仍加载旧代码（Host 半需插件关→开或重启应用），本步无法在真实 GUI 里验证。

## 可复用经验

- 改 `SYSTEM_PROMPT` 前先跑 `npm test` 建立绿色基线，改完只跑 `tests/rewrite-prompt.test.js` 快速迭代，最后再全量。
- `SYSTEM_PROMPT` 是逐行数组拼接，测试断言要选不跨行的片段；跨行片段在 `toContain` 里会因换行与缩进而失配。
- 用 `node --input-type=module -e "import { SYSTEM_PROMPT } ..."` 打印拼好的全文，比读数组直观，能发现行宽与空行问题。
